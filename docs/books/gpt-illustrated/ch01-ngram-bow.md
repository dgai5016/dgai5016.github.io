《GPT图解》从最不起眼的地方开工：不谈神经网络，先教计算机数词频。这一章用两个诞生于半个多世纪前的经典方法——N-Gram 和词袋模型（Bag-of-Words）——搭起语言模型的地基。解读按「问题 → 概念 → 实验 → 误区 → 自测」五段走。

## 一、本章解决什么问题：让计算机判断一句话「像不像人话」

什么是语言模型？原书的定义很严谨：一个用来估计文本概率分布的数学模型——它能算出某个文本序列在自然语言中出现的概率，因此也就能根据给定文本预测下一个最可能出现的词。换句话说，语言模型能判断哪些语句符合自然语言规律、哪些不合逻辑，并在此基础上接着往下写。

这个能力从哪来？受香农熵启发，20 世纪 50 年代的研究者开始用统计方法预测词序的概率。思路朴素到极致：拿一个语料库，数词频。概率不是靠语法规则推出来的，而是「数」出来的——这是全书一切模型的起点。

## 二、核心概念通俗解读

### N-Gram：只许看前几个字的文字接龙

要算一整句话的概率，理论上要计算整个词序列的联合概率，词一多就复杂到算不动。N-Gram 的解法是砍上下文：假设一个词出现的概率仅依赖于它前面的 N−1 个词，只用这有限的 N−1 个词来近似预测下一个词。换个说法，这个「只看前文有限几步」的假设，正是概率统计里马尔可夫假设的思路；N-Gram 模型玩的也因此像一场带规则的文字接龙：不许回看整段前文，只许看前面固定几个字，猜下一个字。

N 是切分长度：Unigram（N=1）是一元组，Bigram（N=2）是二元组，Trigram（N=3）是三元组。原书反复用的例子是「我爱吃肉」：Bigram 切成「我爱」「爱吃」「吃肉」，Trigram 切成「我爱吃」「爱吃肉」。

### 构建四步：分词 → 数频 → 条件概率 → 连乘

原书把 N-Gram 的构建拆成四步，配上书中数字过一遍（Bigram 为例）：

1. 分词：把文本分割成连续 N 个词的组合；
2. 数词频：数每个 N-Gram 出现的次数——书中例子，二元组「我爱」在语料库中出现 3 次，前缀「我」出现 10 次；
3. 条件概率：`P(爱|我)` = 「我爱」的词频 ÷ 「我」的词频 = 3/10 = 30%；
4. 预测与连乘：逐个挑出下一个词、迭代生成整句；把各步条件概率连乘，就近似得到整句话的概率。

### 「词」没那么简单：分词与 Token

「Gram」源自希腊语词根，意为「字母」或「写作」，指文本中的一个元素——在英文中可以是单词、字符，也可以是子词；在中文中可以是词、短语，也可以是字。

子词（Subword）是把词切得更碎的元素，为的是对付未登录词（词汇表里查不到的词）、拼写错误和词汇变化，同时减小词汇表大小。BERT 等模型常用 WordPiece 和 SentencePiece 两类子词分词算法，它们能根据训练数据自动学习出高频子词：WordPiece 把 "playing" 切成 `["play", "##ing"]`、"unstoppable" 切成 `["un", "##stop", "##able"]`，其中双井号 `##` 标记该子词是黏附的前缀或后缀，不是独立的词。

分词是 NLP 关键的预处理环节，切出来的一个个元素就叫 Token。原书吐槽 Token 的中文翻译常常词不达意——「令牌」「子词」「分词」都有人叫；看到它只需知道：语料已被切成语言模型能读取处理的单元。工具上，英文分词常用 NLTK、spaCy，中文用 jieba，用 BERT 则要配它的专属分词器 Tokenizer。

### 词袋模型：把句子倒进袋子摇一摇

N-Gram 预测一个词只考虑前面 N−1 个词，计算简单，但无法捕捉距离较远的词之间的关系。词袋模型干脆走了另一条路——不管顺序。

词袋模型把文本中的词看作一个个独立的个体，不考虑它们在句子中的顺序，只关心每个词出现的频次。换个说法，就像把一句话倒进袋子摇一摇：倒出来只剩一张词频清单，谁在前谁在后全忘了。原书的例子：

- 「咖哥喜欢吃苹果」→ `{"咖哥": 1, "喜欢": 1, "吃": 1, "苹果": 1}`
- 「苹果是咖哥喜欢的水果」→ `{"苹果": 1, "是": 1, "咖哥": 1, "喜欢": 1, "的": 1, "水果": 1}`

比较向量相似度，就能判断两句话关联性的强弱。这一招在文本分类、情感分析等场景里很好用。

### 余弦相似度 vs 欧氏距离：看角度不看距离

衡量向量相似度有两条路。余弦相似度公式：`cos(A,B) = (A·B)/(‖A‖×‖B‖)`——分子是点积，分母是两个向量长度（范数）的乘积。取值 −1 到 1：越接近 1 越相似，接近 0 表示无明显相似性，越接近 −1 越「相反」。

两者区别，原书说得很清楚：余弦相似度关注向量之间的角度而不是距离，适合「只关心方向、不关心大小」的场景——文本、图像这类高维数据看方向比看距离更有意义，还能减少句子长度差异带来的影响；欧氏距离关注实际距离，两个向量越近距离越小，适合聚类分析、推荐系统这类需要真实距离的场景。

### 词袋模型的两大缺陷

1. 高维稀疏：每个词对应词汇表中的一个维度，向量长度等于词汇表大小，计算效率低；
2. 无语义：忽略了词在文本中的上下文信息，单词在向量空间中的相对位置没有意义，无法捕捉语义关系。

这两条缺陷正是下一章的引子：用低维稠密向量表示单词，同时借 N-Gram 式的子序列捕捉上下文——那就是词向量。

## 三、书中实验讲解

### 实验一：Bigram 字符预测模型——亲手造一个语言模型

程序架构六步：构建语料库 → 分词 → 统计 Bigram 词频 → 计算概率 → 定义生成函数 → 生成连续文本。

语料是 6 句话：「我喜欢吃苹果」「我喜欢吃香蕉」「她喜欢吃葡萄」「他不喜欢吃香蕉」「他喜欢吃苹果」「她喜欢吃草莓」。分词函数把句子按单字切分——注意这次 Gram 是「字」不是「词」。

统计词频的核心一行是 `ngrams_count[prefix][token] += 1`：外层键是前缀字，内层统计「下一个字出现了几次」。书中输出：`吃: {'苹': 2, '香': 2, '葡': 1, '草': 1}`，`他: {'不': 1, '喜': 1}`。

转概率的核心一行是 `count / total_count`（该 Bigram 次数 ÷ 前缀总次数）：`吃: {'苹': 0.33, '香': 0.33, '葡': 0.17, '草': 0.17}`，`他: {'不': 0.5, '喜': 0.5}`。到这一步，一个 N-Gram 语言模型就造好了。

生成策略简单直接：`max(next_token_probs, key=next_token_probs.get)`——永远挑概率最大的下一个字。从「我」出发顺着概率表走：「我」→「喜」（概率 1.0）→「欢」（1.0）→「吃」（1.0）→「苹」（0.33，并列最高中先出现）→「果」（1.0），生成了「我喜欢吃苹果」。输入一个前缀，模型立刻吐出一个句子——这就是最原始的文本生成。原书点评：它虽有局限，但对后来许多更强大的 NLP 技术有很大启发。

### 实验二：词袋 + 余弦相似度——句子像不像，热力图说话

这次 Gram 换成「词」，程序结构也是六步：构建语料库 → jieba 分词 → 创建词汇表 → 生成词袋表示 → 计算余弦相似度 → 可视化。

语料是 5 句电影相关的话，如「我特别特别喜欢看电影」「这部电影真的是很好看的电影」。jieba 把第一句切成 ['我', '特别', '特别', '喜欢', '看', '电影']。

词汇表给每个词分配索引，语料库共 22 个词：{'我': 0, '特别': 1, '喜欢': 2, '看': 3, '电影': 4, …}。词袋表示的核心一行是 `sentence_vector[word_dict[word]] += 1`：先建一个全 0 向量，句中出现哪个词就在它那一维加 1。「我特别特别喜欢看电影」→ [1, 2, 1, 1, 1, 0, …]（22 维，「特别」出现两次所以是 2）。

余弦相似度函数三行算完：`np.dot` 求点积、`np.linalg.norm` 求两个范数、相除返回。5 句话两两比较得 5×5 矩阵，用 matshow 画成热力图。原书的观察结论：「这部电影真的是很好看的电影」和「电影院的电影都很好看」交叉处的单元格颜色相对较深——它们共享「电影」「很」「好看」等词，词频向量方向接近，余弦相似度高，语义上确实更相似。

## 四、易错点/误区

**条件概率不是联合概率**。模型真正统计、存储、拿来预测的是条件概率 `P(下一个|前缀)`——`P(爱|我) = 3/10 = 30%` 的含义是「在『我』出现的前提下，下一个词是『爱』的概率」。整句话的概率不是直接数出来的，而是把各步条件概率连乘近似出来的。别把 30% 说成「『我爱』这个序列出现的概率」。

**One-Hot 是词袋的特例**。原书「咖哥发言」明确说：One-Hot 编码可看作一种特殊的词袋表示——单词独立成句时（如「我」单独成句 → [1, 0, 0, …, 0]），词袋表示完全等价于该词的 One-Hot 编码。

**余弦相似度看角度不看距离**。两个向量只要方向一致，哪怕长度差很多，余弦相似度也是 1；欧氏距离则会被长度差主导。文本比较关心「用词分布像不像」（方向），不关心「句子长短」（大小），所以词袋配余弦。手算两个极端：A = [1, 2, 1, 1, 1]（「我特别特别喜欢看电影」在 5 词小词表下）与自己比较：点积 = 1+4+1+1+1 = 8，范数乘积 = √8 × √8 = 8，cos = 8/8 = 1，完全相同；「我」的 One-Hot [1, 0, 0, 0, 0] 与「特别」的 [0, 1, 0, 0, 0]：点积为 0，cos = 0，正交、毫无重叠。

**N-Gram 与词袋**是两个容易背串的模型，对比着记：

| | N-Gram | 词袋 BoW |
|---|---|---|
| 顺序信息 | 保留相邻 N 个词的局部语序 | 完全丢弃 |
| 关心的量 | 条件概率（接龙） | 词频向量（清单） |
| 主要用途 | 语言建模、文本生成、语音识别 | 文本分类、情感分析、信息检索 |

## 五、复习自测

先自己答，再看参考答案。

1. 语言模型的严格定义是什么？它和「预测下一个词」是什么关系？
2. 写出 N-Gram 构建的四步。「我爱」词频 3、「我」词频 10 时，`P(爱|我)` 是多少？
3. Gram 一定指「词」吗？WordPiece 把 "playing" 切成什么，`##` 代表什么？
4. 词袋模型为什么选余弦相似度而不是欧氏距离？值域和含义是什么？
5. 词袋模型的两大缺陷是什么？它们如何引出下一章的词向量？

**参考答案**

1. 估计文本概率分布的数学模型，能算出文本序列在自然语言中出现的概率；知道各序列的概率，自然能选出给定前文下最可能的下一个词。
2. 分割成 N-Gram → 统计词频 → 用「N-Gram 词频 ÷ 前缀词频」算条件概率 → 预测下一个词并连乘得整句概率；3/10 = 30%。
3. 不一定。Gram 指文本中的元素，可以是词、字、字符或子词；"playing" → ["play", "##ing"]，`##` 表示该子词是黏附的前缀或后缀，不是独立的词。
4. 文本向量是高维数据，关心用词方向而非句子长短；余弦只看角度、不受向量长度影响，还能减少句子长度差异带来的干扰。值域 −1 到 1：接近 1 越相似，接近 0 无明显相似性，接近 −1 越相反。
5. 高维稀疏表示导致计算效率低；忽略上下文、无法捕捉语义关系。因此研究者转向低维稠密的词向量，并借 N-Gram 式子序列捕捉上下文——即第2章内容。
