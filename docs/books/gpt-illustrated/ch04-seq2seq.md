前几章从 NPLM 一路走到 RNN、LSTM，模型学会了「读」：用向量表示词，用隐藏状态记住前文。但它们都缺一样本事——把读进来的东西再「写」出去。翻译、摘要、对话全是「进一段、出一段」的任务，且进出长度还不相等。本章的 Seq2Seq 架构就是为此而生，原书还特意点明：它正是 Transformer 的基础架构。这篇解读按「问题 → 概念 → 实验 → 误区 → 自测」五段走。

## 一、本章解决什么问题：「进一段、出一段」难住了谁

拿翻译来说，输入「咖哥 喜欢 小冰」是 3 个词，输出「KaGe likes XiaoBing」是 3 个词，换个句子两边词数就都不一样了。这种「序列进、序列出、长度还不等」的任务，前几章的模型都接不住。

原书说，起初人们尝试用**一个独立的 RNN** 来做，让它既负责读入（编码）又负责写出（解码），效果并不理想——一个网络同时处理输入和输出两套序列，容易出现信息损失。Seq2Seq 的解法是**分工**：编码器（Encoder）里嵌一个 RNN 专门读，解码器（Decoder）里再嵌一个独立的 RNN 专门写，两边各司其职，信息损失的问题就这样被有效化解。这套架构由伊利亚·苏茨克维（他后来成为负责研发 ChatGPT 的首席科学家）等人在 2014 年的论文《Sequence to Sequence Learning with Neural Networks》中首次提出。

原书给的总类比很传神：**通信模型**。电报和电话系统里，文字和声音先被编码成电信号，传输到另一端的接收器再解码还原。翻译也一样——中文句子被「编码」成一个向量传过去，再从向量里「解码」出英文句子。

## 二、核心概念通俗解读

### 编码器：读完做张摘要便签

编码器逐词读入源句子，每个时间步更新一次隐藏状态（hidden state，白话：RNN 一路滚动攒下的「记忆」），读到最后产出**上下文向量**——一个固定大小的向量，装着整句话的信息。换个说法：就像读完一段话，把要点写在一张摘要便签上。这张便签的「字数」（维度）是固定的，句子再长也只能写这一张。

### 解码器：照着便签逐词复述

解码器拿上下文向量作为**初始隐藏状态**——便签就是它的起笔依据——然后一个词一个词往外蹦。关键机制叫**自回归**（autoregressive）：每生成一个词，就把这个词喂回去当下一步的输入，即「用自己刚写的接着写」。书里的示例：模型读完「咖哥很喜欢小冰」，先输出 KaGe，再把 KaGe 喂回去输出 likes，如此往复，直到输出结束标记后停止。

起止靠两个特殊符号管着：`<sos>`（start of sequence）告诉解码器「从这里开始」；`<eos>`（end of sequence）告诉它「到此为止」。有了 `<eos>`，模型才知道什么时候闭嘴——否则它不知道要生成到哪一步。

### 教师强制与曝光偏差：训练时的「老师带读」

训练时如果让还很笨的解码器纯靠自己逐词生成，效果会很差。所以训练阶段用了**教师强制**（Teacher Forcing）：喂给解码器的不是它自己生成的词，而是真实目标句里的词——好比老师带着读，每个字都从正确的前文出发，学得又快又稳。

代价是**曝光偏差**（Exposure Bias）：训练时解码器看到的永远是对的词，测试时却只能吃自己生成的词——一步错，步步错，训练和测试的数据分布对不上。缓解方案是**计划采样**（Scheduled Sampling）：训练中以一定概率改用解码器自己生成的词当输入，让它慢慢适应「靠自己」，逐步戒掉对老师的依赖。

### BLEU：给翻译打分

书末顺便介绍了机器翻译的常用评估指标 **BLEU**：比较机器译文和人工译文在**词级别**上的匹配度，核心是不同长度 N-Gram 的精度再加权综合；还引入简短惩罚因子（Brevity Penalty），防止模型偷懒只翻半句捞高分。

### 一个埋给下一章的类比

咖哥发言把通信类比又推了一层：电话长距离传输会衰减，要用中继器和放大器给信号「整形」；Seq2Seq 碰到长序列也会信息损失，对应的「放大器」就是**注意力机制**——下一章的主角，本章先埋个伏笔。

## 三、书中实验讲解

实验目标：在 5 句中英对照的小语料上，从零搭一个 Seq2Seq 完成翻译。

**语料长什么样**：每行三句——中文源句、`<sos>` 开头的英文（给解码器当输入）、`<eos>` 结尾的英文（当目标输出），例如：

```text
['咖哥 喜欢 小冰', '<sos> KaGe likes XiaoBing', 'KaGe likes XiaoBing <eos>']
```

对这句做训练数据时，编码器输入形状是 `[1, 3]`（3 个中文词的索引），解码器输入和目标都是 `[1, 4]`（`<sos>` 加 3 个英文词）。`make_data` 函数每轮随机抽一句来训。中英文各建一套词汇表和 word2idx / idx2word 映射——两套语言，两本字典。

**模型怎么搭**：Encoder 和 Decoder 是两个独立类，结构相似——都是嵌入层加 RNN，区别只在解码器多一个线性输出层，把 RNN 输出变成对整个英文词汇表的打分。隐藏维度 `n_hidden = 128`。组合成 Seq2Seq 后，前向传播的灵魂就三行：

```python
encoder_output, encoder_hidden = self.encoder(enc_input, hidden)
decoder_hidden = encoder_hidden          # 编码器的记忆交给解码器当起点
decoder_output, _ = self.decoder(dec_input, decoder_hidden)
```

编码器读完整句后，把最后的隐藏状态直接交给解码器当初始隐藏状态——那张「摘要便签」就是在这儿递过去的。注意 `encoder_output`（每个时间步的输出）本章**完全没用上**，原书明说它留给第5章的注意力机制。

**训练**：400 轮，每轮随机抽一句，交叉熵损失加 Adam 优化器（学习率 0.001）。损失一路走低：第 100 轮 0.0534，第 200 轮 0.0197，第 300 轮 0.0127，第 400 轮降到 0.0063。顺带一提算损失那行 `criterion(output.view(-1, voc_size_en), target.view(-1))`：`view(-1, …)` 把输出拉平成「每行一个时间步、每列一个词的分数」，因为交叉熵函数只认这种二维输入对一维标签的形状。

**测试**：这里最能看出教师强制的边界——测试时**绝不喂真实英文**，否则等于抄答案，测不出真本事。那解码器输入填什么？书里用了个简化招数：1 个 `<sos>` 打头，后面用一串 `<eos>` 占位凑数，总长度钉死为和输入句相同，然后一次前向、逐步取概率最大的词。结果两句全对：

```text
咖哥 喜欢 小冰 -> ['KaGe', 'likes', 'XiaoBing']
自然 语言 处理 很 强大 -> ['NLP', 'is', 'so', 'powerful', '<eos>']
```

书里也坦承这个简化做法的毛病：输出长度被输入长度绑死了，输入输出长度不等时可能翻不全或翻错——第一句末尾的 `<eos>` 就没机会输出。更靠谱的方式是真正的自回归：一个 token 接一个 token 生成，拿自己刚生成的 token 继续喂，直到吐出 `<eos>` 为止。这条路书里留到讲 GPT 时再走。

## 四、易错点/误区

**编码器的 hidden 和 output，谁传给了解码器？** RNN 每个时间步吐两个东西：output 是对各时间步输入的编码，hidden 是滚到最后的「整句记忆」。Seq2Seq 传给解码器的是 **hidden**（当初始隐藏状态）；output 本章闲置，是留给注意力的。别把这两个背串了。

**前向传播里怎么出现了目标序列？** `forward(self, enc_input, hidden, dec_input)` 里那个 `dec_input` 装的可是真实英文——按常理目标值只该在算损失时出现。这不是 bug，正是教师强制：训练时故意把答案的「前文」暴露给解码器。训练和测试的分界线一目了然：

| | 训练时 | 测试时 |
|---|---|---|
| 解码器输入 | 真实英文（`<sos>` + 正确译文，教师强制） | `<sos>` 打头 + 占位符，不喂答案 |
| 为什么 | 模型还弱，跟老师学收敛快 | 要验真本事，喂答案等于作弊 |
| 隐患/代价 | 曝光偏差：测试时没人喂了 | 长度被输入长度绑死（简化做法） |

**上下文向量是信息瓶颈**。原书小结说得直接：长序列里重要的上下文信息全被压进一个固定长度的向量，解码时模型难以正确关注到所有重要信息——这就是基于 RNN 的 Seq2Seq 的核心短板，也正是注意力机制要治的病。本章越觉得「一张便签不够用」，下一章就越看得懂注意力为什么非来不可。

**教师强制 ≠ 全程都用**。它只存在于训练阶段；计划采样则是两者之间的过渡态，按概率掺入模型自己生成的词。

## 五、复习自测

先自己答，再看参考答案。

1. 用一个独立 RNN 做翻译为什么效果不好？Seq2Seq 用什么思路解决？
2. 编码器最后交出去的是 output 还是 hidden？它到了解码器里当什么？
3. `<sos>` 和 `<eos>` 分别解决什么问题？
4. 教师强制是什么？它带来什么副作用？用什么技术缓解？
5. 书中测试时解码器输入是怎么构造的？这个做法有什么毛病？

**参考答案**

1. 一个 RNN 既编码又解码，同时处理输入和输出两套序列，容易信息损失；Seq2Seq 把两者拆开，编码器和解码器各嵌一个独立 RNN，分工处理。
2. 交的是 hidden（最后一步的隐藏状态），它作为解码器的初始隐藏状态，充当整个源句子的总结，帮解码器生成第一个目标词；output 留给第5章的注意力机制。
3. `<sos>` 告诉解码器何时开始生成目标句；`<eos>` 教它在何处结束生成，没有它模型不知道该停在哪一步。
4. 训练时把真实目标序列中的词（而非模型自生成的词）喂给解码器当输入，收敛更快；副作用是曝光偏差——训练时总看正确词、测试时只能靠自己，分布不匹配。计划采样按一定概率改用模型自己生成的词，逐步适应。
5. 用 1 个 `<sos>` 加一串 `<eos>` 占位，长度与输入句相同，一次前向后逐步取最大概率词；毛病是输出长度被输入长度钉死，长度不等时会翻不全或翻错（正经做法是逐 token 自回归直到 `<eos>`，GPT 章详述）。

走到这里，模型第一次实现了「读进来、写出去」。但那张固定大小的摘要便签，终究装不下太长的句子——下一章的注意力机制，就是让解码器译到哪儿、就能回看原句到哪儿。
