第 7 章结尾留了个念想：几万参数的 Wiki-GPT 装不下上亿 token 的 WikiText2，生成的前几个词像样，随后就开始绕圈复读；出路是「站在巨人的肩膀上」微调预训练大模型。第 8 章把这条路走完：先用一份聊天语料把只会接龙的 Wiki-GPT 调教成能对话的简版 ChatGPT，再借 Hugging Face 的 GPT-2 重演一遍「预训练+微调」，最后用一个玩具级的 RLHF 实战摸到真 ChatGPT 的最后一块拼图——基于人类反馈的强化学习。全书的代码长征到此收官。

## 一、本章解决什么问题

Wiki-GPT 学的是「看见前文、续下一个词」，你问它天气，它多半接着新闻腔往下编——会接龙，不会对话。而且原书说得很直白：几万参数的教学模型装不下真实世界的语言知识。本章要解决的，就是通往 ChatGPT 的最后一公里：**怎么让一个「会说话」的模型，变成「会好好回答人」的模型？** 答案三级递进：微调教它对话的格式（预训练+微调范式），指令调优让它听懂人的要求，RLHF 让它的回答对齐人类偏好——用原书的话说，让 AI 的目标与人类的目标一致。

## 二、核心概念通俗解读

### GPT 家族进化与伸缩定律

三代三级跳（均为原书数字）：GPT（2018，1.17 亿参数）用「预训练+微调」证明了路线可行；GPT-2（2019，15 亿）文本生成优异，也第一次让人担忧 AI 技术被滥用；GPT-3（2020，1750 亿，当时全球最大）靠零样本/少样本学习出圈——很多时候不用微调，在提示里给零个或几个例子就能应对特定任务。背后是伸缩定律（Scaling Law）：模型性能随规模增长而提高。原书关键技术表里还有两个有意思的说法：参数超过 600 亿时推理能力开始显现；用代码数据训练能让模型获得推理能力（思维链 CoT 的来由），因为代码自带强逻辑。

### 指令调优与对齐

术语白话：指令调优（Instruction Tuning）是拿「人怎么提问、机器该怎么答」的数据微调预训练模型，让它更好地处理对话中的上下文、情感和逻辑；对齐（Alignment）是让 AI 的目标与人类目标一致——理解人类的价值观和道德规则，不产生危害公众安全的回答。换个说法，预训练养出一个聪明但任性的学生，什么都懂一点，但你问东他答西；指令调优教他听题，对齐教他好相处。ChatGPT = GPT-3.5 底座 + 指令调优 + RLHF，并在 InstructGPT 基础上又加了安全性和合规性考量。

### RLHF 三步曲：从「弱弱的 ChatGPT」到左右互搏

原书根据 OpenAI 公开的信息，把 ChatGPT 的训练拆成三步：

| 步骤 | 做什么 | 产出 |
| --- | --- | --- |
| SFT 监督微调 | 从 Prompt 数据库抽样，用监督学习在预训练 GPT-3.5 上微调 | 初始模型，原书昵称「弱弱的ChatGPT」 |
| RM 奖励模型 | 标注员为同一问题的不同答案排序、评估打分，用这些数据训练 | 一个学会了人类偏好的打分模型，能代替人类预估回答的奖励 |
| PPO 强化学习 | 拿弱弱的 ChatGPT 抽样对话，RM 打分，结果反馈给模型 | 用近端策略优化（PPO）进一步优化后的模型 |

换个说法，这套流程像培养答题选手：先请老师示范一批标准答案（SFT），再训练出一位会打分的教练（RM），最后选手按教练的分数反复练（PPO）。更要紧的是原书点破的循环：PPO 优化出的更好模型，回头当第 1 步的新初始化——更好的 SFT 给出更好的回答，更好的排序喂出更好的 RM，更好的 RM 给出更准的反馈……像周伯通左右手互搏（原书自己的比喻），一波推着一波越变越强，这正是章名「流水后波推前波」的含义。

### 强化学习六要素

白话定义：强化学习就是让智能体在与环境的交互中不断试错，学一个能让累积奖励最大的策略。原书用飞翔的小鸟游戏讲六个概念，并逐一对照到 ChatGPT：

| 要素 | 小鸟游戏 | ChatGPT 训练 |
| --- | --- | --- |
| 智能体 | 飞翔的小鸟 | 聊天机器人（被训的模型） |
| 环境 | 空地、水管 | 与人类的对话 |
| 状态 | 小鸟位置、与水管的距离 | 对话历史、用户输入 |
| 行动 | 上、下、左、右、停 | 机器人的回答 |
| 策略 | 决定下一步行动的规则 | GPT 模型本身 |
| 奖励 | 撞水管前的飞行距离 | 人类反馈：满意得正奖励，不满意得惩罚 |

### 策略梯度与 PPO 的 Clip

策略梯度：用神经网络当策略，朝着「让累积奖励更大」的方向调整网络参数。麻烦在于普通策略梯度一步迈得太猛，容易把策略练废。PPO（近端策略优化，OpenAI 的 John Schulman 等人 2017 年提出）的核心思想是**限制每次策略更新的幅度**：引入「Clip」机制夹住策略更新中的概率比率，确保新策略与旧策略的相似性，换来更好的稳定性和样本效率。流程三拍子：收集一批经验（状态、行动、奖励）→ 带 Clip 算梯度优化策略 → 更新后重复。

## 三、书中实验讲解

**实验一：Wiki-GPT 微调成简版 ChatGPT。** 语料是 8 行 User/AI 交替的 chat.txt（问天气、求荐书等日常对话）。第一个关键点：微调必须沿用预训练时的 WikiText2 分词器和词表（28785 个词），否则新语料的词索引和模型权重里的索引对不上号，「知识推理也就无从谈起」。ChatDataset 把 User 行切成输入、AI 行切成目标，各加 `<sos>`/`<eos>`，collate_fn 补齐成批；加载 best_model.pt 后训练 100 轮，损失在 1.97 到 0.004 之间震荡走低。原书在此插了个实战技巧：微调数据集小、或与预训练数据相似时，可以**冻结底层**——freeze_layers 靠 `if int(name.split(".")[1]) >= n` 只把第 n 层之上的参数交给优化器，冻结前两层：既省算力，又保住底层学到的通用特征、防过拟合。最后用集束搜索对话，输入 "hi, how are you?" 真的能聊了——只是能力弱，几万参数、八行语料，能到这一步已是「万里长征的第一步」。

**实验二：Hugging Face GPT-2 微调。** 实战中没人从零造模型，都是下载开源的预训练模型。`GPT2LMHeadModel.from_pretrained("gpt2")` 一步载入：词表 50257、词嵌入 768 维、最多 1024 个位置。两个配套细节：一，必须使用与模型匹配的分词器，否则词汇表冲突、预测出错；二，GPT-2 的起始符、结束符、未知符全是 `<|endoftext|>`（ID 50256），没有独立的 `<pad>`，需要手工指定填充符（实际 ID 也落在 50256）。微调 500 轮，损失从 2.23 降到 0.72。测试环节最能看出「语料知识被捕捉到了」：问天气，回答里冒出一串 "app"——语料里的标准答案正是「请查天气网站或应用」；求荐书，回答是 "ockingbird Lee Harper Harper Taylor"——作者名对了，书名却缺了一截。原因是书名里的 Mockingbird 对 GPT-2 是未收录的整词，分词器把它拆成 'M'、'ocking'、'bird' 三个 token（GPT-2 用的正是 BPE 子词切分，生词拆片段），解码时漏了开头的 'M'。胡话里透着语料的知识，这个例子比任何指标都直观。原书小结还对比了两条路线：Wiki-GPT 底子省时省资源，但受限于维基领域；GPT-2 预训练数据更丰富、泛化更好，代价是更多算力和平台学习成本。

**实验三：玩具级 RLHF。** 三步走。第一步建人类反馈数据集，4 条人工评分：「法国首都」答 "Paris." 得 5 分、答 "Rome." 得 1 分；「怎么煮意面」答 "first boil water." 得 4 分、答 "microwave." 得 2 分，RLHFDataset 每条样本比普通数据集多返回一个 score。第二步设计奖励函数，核心一行 `correct = (predictions == targets).float() * scores.unsqueeze(1)`：预测与目标逐位比对，对的位记人工分、错的记 0，求和后除以有效（非填充）位数，再除以本批最高分，把奖励归一到 0~1。拿小数字代进去：设 "Paris." 连结束符共 3 个有效 token，模型对了 2 个，人工 5 分、批内最高也是 5 分，则 reward = (2×5)÷3÷5 ≈ 0.67——对得越多、人工分越高，奖励越接近 1。第三步把奖励织进损失：`weighted_loss = torch.sum(loss * (1 - rewards)) / rewards.numel()`，即 `Σ(loss×(1−reward))÷N`。(1−reward) 像一个纠错力度旋钮：奖励 0.9 的样本只出 0.1 份力，奖励 0.1 的样本出 0.9 份力，训练重心自动压向人类不满意的回答。100 轮下来，平均奖励从 0.158 爬到 0.667，加权损失从 0.908 降到 0.196——奖励升、损失降，策略梯度训练成形。再测试：问意面满篇 water（正是 4 分答案「先烧开水」的关键词），问法国首都混着 Rome 的残影。原书的结论很坦诚：模型确实从数据集中捕捉到了信息，但这个 RLHF 版本「非常原始」，离复现 ChatGPT 还差十万八千里。

## 四、易错点 / 误区

**1. RLHF 三步有先后，但不是一条死流水线。** 顺序不能乱：SFT 在前（先有会答题的底子，它的输出才凑得出排序数据），RM 居中（学的是人类对 SFT 答案的排序），PPO 在后（按 RM 的分数练）。但走完第三步不是结束——优化后的模型回到第一步当新初始化，循环往复。把它背成一次性流程，就丢掉了 ChatGPT 持续变强的引擎。

**2. 真正的奖励模型是「学出来的」，不是人写的规则。** 书里的 reward_function 是教学替身——手工设计的打分规则；真 ChatGPT 的 RM 是用人工排序数据训练出来的神经网络，能代替人类预估新回答的奖励。别把简化版当成官方做法，它只负责帮你看清「奖励如何进入损失」。

**3. PPO 的 Clip 防的是「一步迈太大」，不是防胡说。** Clip 限制的是策略更新的幅度（新旧策略的概率比率），防止单次更新毁掉之前学好的策略，买来稳定性。回答质量本身来自奖励信号，不来自 Clip。

**4. 微调必须「模型+分词器」成套换。** Wiki-GPT 微调要沿用 WikiText2 词表，GPT-2 微调要用官方 tokenizer——词与索引的对应关系一变，权重里的知识就接不上。顺带的坑：GPT-2 没有独立填充符，特殊符号习惯（自建 `<sos>`/`<eos>` vs `<|endoftext|>`）也不同，照搬上一章的预处理代码会埋雷。

**5. 冻结的是底层，不是顶层。** 原书做法是冻结前 n 层、只微调上层：底层学的是通用语言特征，值得保；上层更贴近具体任务，值得调。方向记反，就把最该保留的东西拿去乱改了。
