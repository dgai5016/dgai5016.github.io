今天，我们推出生命科学验证计划（Life Sciences Verification Program，LSVP），让生命科学专业人士能够在一套经过调整、对生物学相关工作更为宽松的安全防护下使用我们的 Mythos、Opus 和 Sonnet 模型。我们此前已通过早期访问计划接入了数十家组织，现在向更广泛的生命科学社区开放申请（在此申请）。该计划以测试版形式推出，初期面向团队和机构。我们会持续改进该计划，并逐步向个人 Pro 和 Max 套餐扩展访问。

LSVP 旨在让生命科学专业人士能够在广泛的任务中使用我们的模型——这些任务目前在正式发布的 Fable 模型中会被拦截，例如药物发现、研究生物学、临床开发和生产制造。它面向各类团队——从学术实验室到初创公司、制药企业等。

## 验证与授权类型

要获得这些授权，每位申请者都要经过一个验证流程，包括审查其研究资质、安全标准以及伦理研究监督机制。通过验证后，团队可根据自身访问需求申请两类 LSVP 授权：“标准使用”（Standard Use）或“高风险使用”（High-risk Use）。这些授权可在我们的所有产品端使用，包括 Claude Science、Claude.ai、Claude Code 和 API。

标准使用授权适用于大多数生命科学工作，涵盖绝大部分生物学研发工作流。这类授权可以扩展到整个团队以支撑多样化的日常工作，每年续期一次。它让这些团队可以使用我们的 Mythos、Opus 和 Sonnet 模型，并配备经过调整的分类器——相比正式发布的模型，它们对科学任务更为宽松。标准使用授权目前适用于 Mythos 5.1、Opus 5 和 Sonnet 5，未来也会随新模型发布同步适用。它是专为支撑生命科学活动的完整版图而设计的，领域涵盖基础科学、研发、供应链与生产制造、临床开发、质量保证、法规事务、投资与尽调等。

尽管我们预计标准使用授权能覆盖绝大多数访问需求，但有些工作被滥用的潜在风险更高，因此需要额外的审查。

高风险使用是一种附加授权，面向从事标准使用授权下受限领域工作的团队。它会移除所有拦截生命科学请求的安全防护。这种授权针对单一研究项目而非整个团队，且必须每六个月续期一次。通常，一名涉及两用性研究的研究者会持有一项用于日常多样工作的标准使用授权，以及一项或多项仅适用于特定项目工作的高风险使用授权（例如，刻画某一特定病毒载体家族如何被人体免疫通路识别）。

Claude Opus 5 和 Claude Sonnet 5 的高风险授权即日起可用。我们正与美国政府合作，让 Claude Mythos 的高风险授权能够更广泛地提供，但在本次发布之时，Mythos 的高风险授权仍仅限于一小部分经过额外审查的实体。

所有其他安全防护（例如网络安全分类器）在 LSVP 授权下仍然有效。

## 通过共同责任实现可信访问

正如我们在最近的威胁报告中所展示的，平台上出现的滥用企图日益复杂，其中包括可能支持生物武器开发的尝试。在生物学领域，往往无法区分一个正在做正当工作的用户（例如研究某种病毒病原体以开发针对它的疫苗）与一个意图作恶的用户（例如恶意尝试提高某种病毒的传播性），因此最令人担忧的威胁模型是：合法访问权限被恶意行为者转移或窃取。事实上，内部威胁和违规滥用一直是重大生物安全事件与恐慌的主要诱因。在制定 LSVP 的安全防护时，我们特别针对以下三种威胁模型进行了防护：

- 访问权限失守：恶意软件或账号被接管，把访问权限转移到恶意行为者手中
- 内部威胁：恶意或受胁迫的员工蓄意采取恶意行动，或将其访问权限转移给恶意行为者
- 智能体误用：智能体（尤其是以集群方式或长周期任务运行时）采取意料之外的危险行动

为了防御这些威胁，我们与企业首席信息安全官（CISO）密切合作，围绕“共同责任”理念设计了新的 LSVP 安全防护：将实际使用情况与模型访问的预期用途进行对照监控。由于我们对 LSVP 组织的生命科学可信度和监督机制做了审查，我们可以放心让它们自行界定其计划内团队或项目的安全使用标准。

每个实体的访问权限都与其在授权申请中声明的用例绑定，我们会持续监控 LSVP 流量，以识别超出所声明安全范围的使用行为或模式。一旦出现未授权活动，我们可以将相关情况标记给组织管理员，让他们在事先约定的时间范围内对事件进行分级处置和补救。用例说明应包含对预期工作的高层次描述——就像人们在招聘启事中会写的那种——且不得包含任何敏感信息或知识产权。

## LSVP 中的监控如何运作

严重的滥用行为往往分散在大量请求和会话中，让彼此看起来毫无关联，从而逃避检测。在 LSVP 中，我们正把安全防护从实时拦截——即在每个请求发出时拒绝潜在有害的访问——转向离线监控，后者能让我们更清晰地从行为模式中识别潜在滥用。把执行机制从实时拦截改为离线监控，可以让正当工作少受打断，但这要求我们保留与被标记活动相关的数据以供审查。针对 LSVP 流量，我们要求保留数据 30 天，以便有效开展这种监控。

这些数据被严格隔离，不会用于模型训练，Anthropic 生命科学研究团队的成员也无权访问。对于符合条件的组织，我们还在研究 LSVP 如何与我们企业级前沿安全防护（Enterprise Frontier Safeguards，EFS）系统的功能相集成。

## 申请与可用性

有意加入 LSVP 的组织可在此提交申请。我们预计第一周内将登记数百家组织，并在未来数周进一步扩大计划规模，以支撑生命科学社区的大多数成员。

目前，LSVP 已在我们面向 API 使用的第一方控制台中开放，也可在 Claude for Enterprise 和 Team 套餐中使用。我们尚未支持个人套餐，但正在努力为这类用户扩展访问。第三方平台也暂不可用。

作为测试版，LSVP 尚不对启用 BAA 的组织开放。这意味着持有 PHI 数据的客户应使用单独的、未启用 BAA 且不受 HIPAA 覆盖的组织。

在 API 和 Claude Science 中，用户可以原生地在不同授权之间切换。在 Claude.ai 和 Claude Code 中，初期只有预先选定的默认授权生效（使用 Claude Code 并通过 API 身份验证时除外）。对绝大多数用户来说这不会有影响，因为他们只会用到标准使用授权。不过，我们会随着时间推移改进这些 LSVP 功能的支持程度与可移植性。

提供这些前沿能力，是我们支持生命科学社区的更广泛努力的一部分——我们与这个社区肩负着共同使命：加速治愈疾病、改善人类健康。未来几个月，我们将分享更多关于新产品、研究合作以及计划改进的信息。
