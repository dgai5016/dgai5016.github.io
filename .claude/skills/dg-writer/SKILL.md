# dg-writer：博客写作技能集大成者

本技能是**主路由**：只做三件事——识别写作类型、按路由表分发到 `rules/` 下规则文档、定义所有类型共用的通用契约。具体写作流程全部在规则文档里。

## 路由表

| 写作类型 | 识别特征 | 规则文档 |
| --- | --- | --- |
| AI 论文翻译 | arxiv 论文 / 论文标题 / 「翻译论文」「论文译文」 | `rules/ai-paper-translation.md` |
| （预留）AI 概念解读 | 「解释下 AI 的 X」「X 是什么意思」 | 迁移自 dg-skills:dg-writer-ai-explainer，待建 |
| （预留）技能使用指南 | 「给 X skill 写使用说明」 | 迁移自 dg-skills:dg-writer-skill-guide，待建 |
| （预留）资料总结 | 已有独立技能 dg-summarize-resources，不并入 | — |

**路由失败处理**：写作类型匹配不上任何规则时，明确告知用户当前支持的类型清单，不要硬套最接近的规则。

## 通用契约（所有写作类型都必须遵守）

### 产出物边界

- 产出是**给读者看的公开博文**，正文中禁止出现两类自指信息：
  1. **维护元信息**：技能名、脚本路径、如何触发、目录约定等内部约定；
  2. **制作工艺描述**：产物自身是怎么做出来的（公式用什么渲染、图表存在哪、译文页开头有什么结构、「本文如何翻译/维护」之类的说明）——读者打开页面自然看得到，预告即是废话。
  
  唯一允许的元信息是长期文章顶部的「最近更新：日期」行。合集主文章开头只用一句话说明定位（这是什么合集），不展开工艺。
- frontmatter 规范：`date` 用真实当前北京时间（写前先执行 `TZ=Asia/Shanghai date "+%Y-%m-%d %H:%M"`）；每篇文章仅一个标签。
- 临时产物只落 `/tmp/` 下对应技能目录，绝不进仓库。
- 不 commit/push（提交走 dg-git-push）；写完 `npm run dev` 让用户在浏览器验收（5173 已有服务就不重启）。

### ⚠️ 数学公式坑（KaTeX）

博客用 KaTeX 渲染公式。**成对 `$` 之间的中文会被当公式吃掉**：

- 翻译含公式的文本时，`$...$`（行内）/ `$$...$$`（块级）内部的 LaTeX **原样保留、不翻译、不拆开**
- 公式标记当原子 token 整体搬移，中文文本绝不能写进 `$` 定界符之间
- 美元金额一律中文金额表述（15 美元），正文不出现裸 `$`

### 翻译一律走 baoyu-translate（dg 的全局规则）

任何类型的翻译（论文、新闻、文档）都必须通过 `Skill(baoyu-translate)` 执行，**不许裸译**：默认 refined 模式，仓库根 `.baoyu-skills/baoyu-translate/EXTEND.md`（受众/风格/核心术语表）自动加载；领域特有约束（公式原子性、美元金额中文化等）在调用指令里额外传递。各规则文档的翻译步骤里已写明具体调用方式。

### 新增长期文章的通用收尾

如果产出包含新的合集主文章（如《AI 论文翻译》《Claude 生态更新动态》这类持续追加的索引文）：

1. 主文章进 `docs/posts/`（进首页文章流，单标签）
2. 明细页放 `posts/` glob 之外的独立目录，用 `<PostLink to="/<目录>/<slug>">` 组件以浮层打开（`PostLink` 已全局注册；插槽内只放纯文本，不放 markdown 语法）
3. 需要把新目录加进 `docs/.vitepress/theme/components/PostOverlay.vue` 的 `import.meta.glob` 懒加载列表（改完必须重启 dev 才生效——glob 是构建期展开）
