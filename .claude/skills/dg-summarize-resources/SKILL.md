# dg-summarize-resources：外部资料总结 → 博文（主路由）

输入（外部资料 + 零散笔记）→ 路由到对应规则文档 → 产出一篇「N 条资料总结」博文，落在 `docs/posts/summary-resources/`。

本文件是主路由，不包含具体资料类型的抓取细节——那些在各规则文档里。执行时：**先读通用契约，再按路由表跳到对应规则文档，严格按其步骤走。**

## 通用契约（所有资料类型共用，规则文档不得违反）

### 10 条原则

1. **以 dg 的笔记为种子**：dg 记下的点优先保留原意，是总结的骨架，不许丢弃或扭曲
2. **目标恰好 10 条**：不足时按对应规则文档的补足策略补齐
3. **绝不编造**：补不足时如实输出 N 条（N < 10），标题同步写 N 条，并告知原因
4. **条目格式**：每条 = 加粗要点句 + 1~3 句展开；展开要具体（有数字/例子/因果），不说空话
5. **排序**：按内容逻辑排（是什么 → 为什么 → 怎么做 → 边界）；dg 的笔记条目在前，补足条目自然融入，**不区分标注来源**

### 输出规格

- 目录：`docs/posts/summary-resources/`（`posts/**/*.md` 全量收录，自动进首页/归档/标签页/命令面板，无需改任何数据层代码）
- 文件名：视频 BV 号全小写（如 `bv1xx411c7md.md`）；无 URL 时用标题音译的英文 slug
- frontmatter 模板（5 字段，与全站文章一致）：

```yaml
title: 看完《资料名》的 N 条资料总结   # N=实际条数，凑满 10 才写 10
date: <真实北京时间，取法见下>
tags: [资料总结]
excerpt: 一句话：这个资料讲什么 + 最大亮点
layout: post
```

- date 取法：写 frontmatter 前先执行 `TZ=Asia/Shanghai date "+%Y-%m-%d %H:%M"`，用其输出填 date

### 写作规范

- 中文行文
- 公开仓库内容安全：不含个人路径（如 `/Users/...`）、用户名、邮箱、API key 等
- 每篇文章仅一个标签（全站约定），本类目固定用 `[资料总结]`

## 验收规范

- 文章写完直接 `npm run dev` 让 dg 在浏览器看活文章；已发现 5173 端口在跑时不换端口
- 成文自检（在开 dev 前）：把每条与 dg 的原笔记逐条对照，重点核对公式、等式、数字、引述的**方向与位置**是否保真（实战学费：曾把「等式左边补动手」错写成「等式右边还差一项」）
- 不主动 commit/push；dg 说「提交/push」或调用 dg-git-push 才提交

## 扩充指南（未来加新资料类型）

1. 新建 `rules/<类型>.md`，骨架与 bilibili.md 一致：输入 / 整理笔记 / 信息抓取 / 补足策略 / 撰写博文 / 验收 / 失败处理 / 坑位清单 / 边界
2. 本文件路由表加一行
3. frontmatter description 的触发词补上对应说法

## 边界

- 不做全文转录、逐字翻译
- 不产出私人笔记——产出是公开博文
- 不生成封面（v1；文章卡片层不显示封面，后续想加随时可加）
- 不主动 commit/push（提交走 dg-git-push）
- 不碰需要登录才能访问的内容（B站 AI 字幕、会员视频等）
