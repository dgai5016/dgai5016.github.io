# dg-book-study：一次读书，双产物（导图 + 章节精讲）

输入书籍 markdown 电子版，产出**复习全套**：全书思维导图（快速定位）+ 每章一篇费曼式解读（深度重学）。核心经济学：分章子代理**读一章同时产出两样**（导图子树 + 章节文章），读书 token 成本摊薄一半。

## 产物与挂载

| 产物 | 位置 | 挂载方式 |
|---|---|---|
| 思维导图 | `docs/public/books/<slug>/mindmap.md` | yaml `mindmap: <slug>` → 预览卡「思维导图」按钮 |
| 章节文章 | `docs/books/<slug>/ch<NN>-<topic>.md` | yaml `dir: <slug>`（已有机制自动扫描挂载到预览卡文档区，PostLink 浮层阅读） |

## 工作流程

### Step 0 输入解析
书名 + md 路径（必填）；slug 沿用该书 yaml 的 dir/mindmap 值。书不在 yaml → 提示先走 dg-add-book。已存在 mindmap.md 时问用户是否跳过导图只补文章（省一次读书）。

### Step 1 章节骨架
```bash
grep -n "^## " <md>   # 章级（### 小节级也扫，注意代码块里 # 注释是噪音）
```
生成章节清单 + 每章行区间。

### Step 2 分章子代理并行（核心）
每章派一个 general-purpose 子代理（章多时合并几章一个），**单个子代理的完整任务**：
1. Read 该章行区间（完整读完含代码）
2. 产出①：该章导图子树（规范同 dg-book-mindmap：4 层为主、极密章可嵌套列表）
3. 产出②：该章费曼式精讲文章，Write 落盘 `docs/books/<slug>/ch<NN>-<topic>.md`
4. 报告返回：文章标题 + 字数 + 段落摘要 + 导图子树（主会话汇总用）

子代理必带上下文：五段式骨架 + 通俗化五手法（见下）+ 忠实原书原则 + frontmatter 模板。

### Step 3 汇总
- 导图子树拼装 → `docs/public/books/<slug>/mindmap.md`
- yaml 确认 `mindmap: <slug>` 与 `dir: <slug>` 都在

### Step 4 验证 + 交付
- curl mindmap fetch 200；书单页 hover 该书 → 导图按钮 + 文档区出现各章文章链接
- 抽查 1 篇文章 PostLink 浮层能打开
- 不主动 commit

## 章节文章写作规范（传给子代理的硬性要求）

### 五段式骨架
1. **本章解决什么问题**——承接上一章的缺陷立起本章问题（技术书叙事线），先立问题知识才有挂靠点
2. **核心概念通俗解读**——逐个讲透本章关键概念（重头戏）
3. **书中实验讲解**——代码验证了什么、关键步骤在干嘛、结果说明什么（不是贴代码）
4. **易错点/误区**——易混概念对比
5. **复习自测**——5 个问题

### 通俗化五手法
1. **类比先行**：抽象概念先给贴切生活类比再上定义（类比要准确，不硬凑）
2. **数字代入**：公式必配一个具体数字手算例子
3. **术语翻译**：黑话首次出现给白话
4. **对比表**：易混概念 markdown 表格左右对照
5. **忠实原书**：知识/例子/实验/数据必须来自原书；补充例子用「换个说法」式引入，不喧宾夺主——**产出的是「这本书的知识」不是「AI 的自由解读」**

### 篇幅与语言
- 每章 1800-3000 字（核心章可到 3000）
- 中文，面向「聪明的零基础读者」（日常中文流利 + 基础数学 + 一点编程，无 AI 背景）
- 公式用行内代码 + Unicode（`Attention(Q,K,V)=softmax(QKᵀ/√d)V`），不用 LaTeX 块
- 代码不整段贴，关键行可引用
- 复习语境，语气自然不说教

### frontmatter 模板
```
---
title: 第N章解读：<本章主题的钩子标题>
date: <TZ=Asia/Shanghai date "+%Y-%m-%d %H:%M" 取真实时间>
layout: post
---
```

## 坑位清单
1. 一次读完全书必炸上下文——分章子代理是硬性流程
2. 继承 dg-book-mindmap 全部坑位（public vs docs 目录、frontmatter 禁忌、markmap 格式限制）
3. 章节文章落 docs/books/<slug>/（会编译成页面，layout: post 必带）；导图落 public/books/<slug>/（fetch 原文）——两个目录别混
4. 子代理 Write 落盘防 `$$` 损坏：文章公式一律行内代码写法（本规范已内建）
5. 章文件名 `ch<NN>-<topic>.md`（两位章号排序友好，topic 用英文 slug）
6. **正文里的 JSON 字典/花括号结构必须包反引号**（如 `{"咖哥": 1}`）：裸写的 `{"k": v}` 会被 markdown-it 解析成前一个 HTML 标签的属性串（`苹果:="" 1,=""...`），Vue 编译报 "Duplicate attribute" 且行号对不上源文件、极难排查（2026-09 踩过 ch01 词袋例子）；`<sos>`/`<pad>` 等尖括号记号同理必须包反引号
7. 公开内容红线：文章与导图都不含个人路径/标识
